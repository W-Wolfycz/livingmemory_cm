# 任务

从以下群聊记录中萃取可长期保存的中性事实记忆。

当前日期时间：{current_date}

## 消息身份

- `<cm_time>…</cm_time>`：消息时间。
- `<cm_speaker current="1"/>`：触发本次检查的当前发言者（群聊）。
- `<cm_speaker/>`：群内其他成员。
- `<cm_speaker bot="1"/>`：Bot 发言。
- `<cm_nickname>…</cm_nickname>`：紧邻的发言者昵称；昵称缺失时显示 `?`。
- 身份标签只用于归因，正文必须使用标签后的具体昵称；不得把不同人的发言、行为、偏好或关系合并到同一人名下，也不得使用「某用户」「对方」等泛称。

## 群聊记录

{conversation}

## 萃取规则

1. 优先提取明确决策、计划、约定、偏好、身份、关系变化和未来可能再次引用的事件。
2. 使用中性、简洁、可验证的表述；不得模仿 Persona，不用第一人称角色口吻，不文学化补写。
3. 同一连续事件或同一主题放在一条记忆中；不同主题、不同时间或彼此独立的事件拆成多条。
4. 每条记忆包含 1 至 5 条 `key_facts`；整批最多 5 条记忆，不按单条消息机械拆分。
5. 群聊闲聊、重复打趣和无后续价值的现场动作可忽略；没有持久价值时输出空数组。
6. 如果因为内容安全或政策原因无法处理，输出 `status=skip`；不要输出道歉或解释文字。
7. 将“今天”“明天”“昨天”“下周”等相对时间转换为绝对日期；无法可靠确定时留空，不猜测。
8. `participants` 只列入该条记忆直接相关的具体昵称；Bot 如直接参与该主题，使用其 `<cm_nickname>` 标签中的昵称。
9. `summary` 是中性主题摘要，只概括该条记忆，不承担人格表达。

## 输出

只输出标准 JSON，不附加说明：

```json
{
  "status": "success",
  "memories": [
    {
      "summary": "中性主题摘要",
      "topics": ["主题1", "主题2"],
      "key_facts": ["具体昵称对应的事实1", "事实2"],
      "participants": ["昵称1", "昵称2"],
      "event_time": "YYYY-MM-DD 或时间范围；无法确定时为空字符串",
      "sentiment": "positive | neutral | negative",
      "importance": 0.7
    }
  ]
}
```

字段限制：`summary` 尽量不超过 220 个中文字符；`topics` 1 至 4 项；`importance` 为 0.0 至 1.0。

无持久信息时：

```json
{"status": "success", "memories": []}
```

无法处理时：

```json
{"status": "skip", "reason": "content_policy", "memories": []}
```
